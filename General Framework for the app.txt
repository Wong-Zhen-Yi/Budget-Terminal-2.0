# One important architectural decision

I **wouldn't have React directly execute Python**.

Instead:

```text
React
  │
  │ HTTP / WebSocket
  ↓
FastAPI
  │
  ↓
Python services
```

For example:

```text
GET /api/portfolio

GET /api/market/NVDA

GET /api/company/NVDA/fundamentals

POST /api/dcf

POST /api/backtest

POST /api/signals
```

And for real-time data:

```text
Market Data
     ↓
Python
     ↓
WebSocket
     ↓
React
     ↓
Chart
```

This makes the application much easier to reason about.

# But there's an even better approach for performance

Don't run a full Python server unnecessarily for everything.

Electron can have:

```text
Electron Main Process
       │
       ├── Window management
       ├── Files
       ├── Notifications
       ├── OS integration
       │
       └── Python Backend
               │
               ├── Financial calculations
               ├── Market data
               ├── Backtesting
               └── AI
```

And React runs in the renderer:

```text
Electron
├── Main
│
├── Renderer
│    └── React
│
└── Python
```

This gives you a clean separation between UI and computation.
